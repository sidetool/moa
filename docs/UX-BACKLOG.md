# 개인 OTT 사용성 후속 후보

검색, 이어보기와 시청 기록의 현재 동작은 [카탈로그 문서](CATALOG.md)에 정리했다. 이 문서는 사용성 리뷰에서 반영한 변경과 남은 후보를 기록한다.

작품 상세의 전후 시즌 이동은 [정규 시즌 모아보기](CATALOG.md#정규-시즌-모아보기)로 제공한다. 외전·특별편은 이 탐색에서 제외하며 별도 관계 목록은 추가하지 않는다.

## 사용성 리뷰에서 채택한 사항

`45d8054`의 검색·재생·설정 흐름을 기준으로 판단했다. 자주 하는 조작이 실패하거나 다음 화에서 선택이 풀리는 문제를 먼저 다룬다.

| 상태 | 채택한 변경 | 확인한 사용자 흐름 |
| --- | --- | --- |
| 반영 | 통합 검색에서 정상 0건과 조회 실패를 구분하고 실패한 요청만 재시도한다. | 한 소스가 실패해도 다른 결과와 TV 포커스가 남는다. 전체 실패 후에도 검색어를 다시 입력하지 않고 복구한다. |
| 반영 | 설정 저장에 실패하면 해당 설정에서 재시도한다. 내 목록 변경의 일시 실패는 앱이 두 번까지 다시 보내고, 끝내 실패하면 버튼은 확인된 상태로 돌아간 채 한 줄로 알린다. | 빠르게 연속 변경한 다른 설정과 이미 기기에 적용한 값이 보존된다. 작품 상세와 쇼츠의 내 목록 버튼은 담기·해제 역할을 유지하고, 쇼츠를 넘긴 뒤 끝난 요청은 누른 작품에만 반영된다. |
| 반영 | 라이브러리 폴더 탐색·추가·스캔 실패를 구분한다. | 폴더 경로와 이름을 유지한다. 키보드로 탐색을 재시도하거나 첫 폴더를 등록한 뒤에도 다음 조작을 이어갈 수 있다. |
| 반영 | 연속 재생 시 선택한 배속을 유지하고 플레이어 회차 목록을 열면 현재 화가 보인다. | 길게 눌러 잠시 사용한 2배속은 이어지지 않는다. 장편 시청 중에도 목록을 열자마자 현재 회차가 보인다. |
| 반영 | 자막 알림에만 자막 변경 동작을 제공한다. 모바일에서 음소거나 볼륨 0을 해제할 수 있다. | 재생 서버가 바뀌었을 때는 전환 사실만 알린다. 소리를 다시 켜면 마지막으로 사용한 0보다 큰 볼륨으로 복구한다. |
| 측정 완료 | 첫 소스 응답부터 첫 작품 카드까지 걸리는 시간과 상세에서 돌아왔을 때의 표시 시간을 측정했다. | 늦게 도착한 판본으로 대표 카드가 바뀌어도 위치와 초점이 유지된다. |

리뷰의 배속 저장 제안은 연속 시청 범위에 적용했다. 한 작품을 빠르게 본 뒤 플레이어를 나가면 다음에 여는 영상은 1배속으로 시작한다. 모바일에서는 소리가 꺼졌을 때 기존 스피커 버튼을 노출해 작은 화면에서 재생 조작에 쓰는 공간을 확보했다.

### 통합 검색 측정 결과

로컬 Chromium에서 소스 두 개가 각각 100ms와 300ms 뒤에 응답하고, 묶기 응답에는 350ms가 걸리도록 했다. 첫 소스에는 47개 작품, 두 번째에는 같은 작품의 다른 판본 47개와 새 작품 하나를 넣었다. 로컬 라이브러리는 비어 있다. 아래는 작품 묶기를 켠 상태에서 두 버전을 번갈아 세 번씩 실행한 중앙값이며 괄호 안은 범위다.

| 사용자가 보는 시점 | 기준 버전 | 수정 후 |
| --- | ---: | ---: |
| 첫 소스 응답 → 화면 안 첫 작품 카드 | 618ms (607–627) | 402ms (399–430) |
| 첫 소스 응답 → 48번째 고유 작품이 목록에 표시됨 | 618ms (607–627) | 593ms (583–595) |
| 상세에서 뒤로 → 캐시된 48개 작품 표시 | 49ms (46–79) | 56ms (50–66) |

기존에는 두 번째 소스가 도착하면 진행 중인 첫 묶기 요청을 취소했다. 이제 첫 묶기와 최신 묶기를 함께 기다려 먼저 확인된 카드부터 표시하고, 대표 판본이 바뀌면 같은 카드를 갱신한다. 상세에서 돌아올 때는 두 버전 모두 새 소스 응답 전에 캐시된 결과를 표시했다. 실제 소스의 네트워크 응답 시간이나 운영 서버 처리량은 이 측정에 포함되지 않는다.

### 후속 구현

- **[홈 이어보기에서 숨기기](CATALOG.md#홈-이어보기에서-숨기기)** — 카드의 ‘더 보기’에서 숨긴다. 현재 프로필의 시청 위치·완료 기록·내 목록을 보존하고, 새로 재생해 진도가 저장되면 이어보기에 다시 표시한다.
- **[자동 자막 싱크로 복원](PLAYBACK.md#자동-싱크-맞춤)** — 수동으로 맞춘 회차에서 보정을 해제할 수 있다. 직접 지정한 0초도 수동값으로 보존한다.
- **[첫 자막 파일 로드 실패](PLAYBACK.md#표시와-저장)** — 브라우저가 WebVTT를 열지 못하면 재생을 유지하고 자막 목록에서 같은 자막을 재시도하거나 다른 자막을 선택할 수 있게 한다.

### 후속으로 채택한 항목

- **시청 완료와 미시청 표시** — 수동 시청 완료와 ‘여기까지 봤어요’가 안 본 회차 수·다음 재생·판본에 미치는 영향을 확인한다.
- **업로드한 자막 삭제** — 본인 업로드 파일의 소유권과 다른 프로필에서의 사용 범위를 확인한다.
- **탐색과 접근성** — 모바일 콘텐츠 탭에서 홈 활성 표시, 한 글자 검색의 제출 안내, 존재하지 않는 회차 번호 안내, 설정 선택 항목의 한글 접근성 이름을 보완한다.
- **실제 화면에서 재현 후 결정** — 모바일 세로 자막 패널은 최대 높이와 자막 위치를 함께 보고, 터치 탐색 미리보기는 최초 누름·바 밖 드래그를 구분한다. 한 소스뿐인 작품에서 소스 블록이 회차를 얼마나 밀어내는지, 쇼츠 준비 지연 중 외부 재생으로 전환할 필요가 있는지도 확인한다.

### 이번에 도입하지 않는 제안

- 검색에는 Esc 후 다시 여는 돋보기와 단축키가 있고, 작품 상세는 이어볼 시즌과 50개 회차 구간을 이미 선택한다. 새 검색창이나 시즌 탐색을 중복해 만들지 않는다.
- 상시 상태 배지·중앙 볼륨 표시·전역 알림, 필터·최근 검색어·설정 검색, 시트 전면 교체는 개별 불편의 빈도와 모바일 공간을 보고 판단한다. 폴더 하나를 추가하려는 관리자에게 전체 설치 체크리스트를 요구하지 않는다.
- TV 홈 배너 조작, 모바일 플러그인 진입점, 다운로드·기록 일괄 관리, 쇼츠 단축키 등은 해당 화면을 다음에 개선할 때 검토한다. 프로필 전환 편의를 이유로 기존 PIN 잠금을 완화하지 않는다.

### 검색·상세의 추가 검토

- 통합 검색은 소스별 첫 페이지를 가져온다. 추가 결과는 소스별 검색에서 탐색할 수 있게 하고, 여러 페이지를 묶을 때의 표시 순서를 확인한다.
- 짧은 간격으로 검색어를 바꿨을 때 이전 검색이 같은 소스의 다음 검색을 얼마나 지연시키는지 측정한다. 같은 요청을 기다리는 다른 사용자가 있으면 해당 작업을 계속한다.
- 작품 수가 많을 때 로컬 제목·원제·별칭 검색과 카드별 회차·진행률 조회 비용을 따로 측정한다. 상세 화면에서도 회차가 준비된 뒤 예고편 등 부가 정보 때문에 재생 버튼이 지연되는지 확인한다.
- 작품 묶기를 켠 검색은 최대 1,000개 ID를 묶는다. 인기 장르처럼 후보가 그보다 많은 경우에도 나머지 작품을 볼 수 있도록, 페이지 경계를 넘는 판본 묶기와 이어보기 위치 유지를 함께 검토한다.
- 애니 상세의 다음 일본 방영 시각·캐릭터와 성우·주제가 정보는 현재 메타데이터의 누락률과 표시 공간을 보고 판단한다. 기존 인물·일정·유사작 기능과 중복되는 항목은 합친다.

### 자막과 재생 후속 실험

- **이어보기 동영상 미리보기** — 홈의 정지 이미지로 시청 위치를 알아보기 어려운 경우를 확인한다. 무음 영상은 원격 스트림과 서버 세션 비용, 터치·리모컨에서의 효용을 측정한 뒤 결정한다.

- **구간별 자막 싱크 실사용 검증** — [실험 옵션](PLAYBACK.md#자동-싱크-맞춤)으로 실제 판본의 오프닝 앞뒤 대사와 수동 보정을 확인한다. 여러 편집 지점이나 재생 속도 차이가 있는 판본은 후속 평가 대상이다.
- **자막 표시 픽셀 검사** — 헤드리스 Chromium의 별도 검사(`verify-subtitle-browser.mjs`)에서 ASS 프레임과 여러 줄 자막의 픽셀 수 판정이 기준 버전 `608ab2e`에서도 실패했다. 실제 화면과 캡처를 대조해 원인을 확인한다.
- **시즌 자막 묶음** — 개별 파일로 판별할 수 없는 경우, 같은 작품·시즌 묶음에서 한 숫자 자리만 달라지고 요청 회차의 후보가 유일한지 확인한다.
- **작품별 번역 용어집** — 회차 사이에서 이름 표기를 일관되게 유지할 수 있도록 출처와 사용자 표기 우선순위, 번역 캐시 버전을 먼저 정한다.
- **Anime4K 실기기 검증** — [기기별 실험 옵션](PLAYBACK.md#anime4k-기기-업스케일링-실험)으로 모바일·TV의 실제 GPU에서 720p·1080p를 10분 이상 재생해 프레임 드롭, 자막과 PiP 동작을 확인한다.
  - 소프트웨어 WebGL에서 GPU 오류를 강제로 일으킨 뒤 작은 재생 창(Document PiP)을 닫으면 원본 영상은 계속 재생됐다. 이때 같은 영상에서 보정을 직접 껐다 켜면 간헐적으로 첫 보정 프레임이 나오지 않았다. 실제 GPU에서도 재현되는지 확인한다.
- **HLS 다운로드 이어받기** — 재시도 전후 영상·음성·구간이 같은 판본인지 검증하는 절차를 먼저 설계한다.
