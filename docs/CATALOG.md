# 카탈로그

작품 검색·묶기·시즌 탐색과 공유 캐시 정책을 설명합니다. 소스 주소 변경에도 ID를 유지하는 규칙은 [소스 식별](SOURCES.md#주소가-바뀌어도-기록-유지)을 따릅니다.

## 검색과 작품 묶기

설정의 작품 묶기를 켜면 같은 작품으로 확인된 카드들을 하나의 그룹으로 표시합니다. 소스별 검색은 독립적으로 진행하며 먼저 도착한 결과부터 그룹을 해석합니다. 그룹 해석 실패 시 원본 카드를 표시합니다. 끄면 원본 소스 카드를 유지합니다.

승인된 TMDB 식별자·미디어 종류·시즌·파트·제목 정체성을 함께 사용합니다. 서로 다른 승인 ID, 영화/시리즈, 특별편/정규 시즌, 더빙/자막 판본을 제목이 비슷하다는 이유만으로 합치지 않습니다. 잘린 제목이나 미확정 회차를 임의로 보완하지 않습니다.

예를 들어 가상 소스 A와 B가 모두 `예제 여행 시즌 2`의 같은 승인 TV ID를 제공하면 그룹 후보가 됩니다. `예제 여행 극장판`이나 `예제 여행 시즌 3`은 별개입니다. 사용자는 상세 화면에서 수동 묶기·분리·초기화를 선택할 수 있고 결과는 프로필에 저장됩니다.

`POST /api/media/groups/resolve`는 `{ "ids": ["example-a", "example-b"], "query": "예제 여행" }` 형태로 요청합니다. 실제 존재하는 미디어 ID만 사용합니다. 대표 카드와 원본 소스 목록은 재생 선택을 위한 정보이며 모든 판본의 길이나 자막이 같다는 뜻은 아닙니다. 시즌 모아보기는 [정규 시즌 정책](#정규-시즌-모아보기)을 따릅니다.

## 정규 시즌 모아보기

`GET /api/media/:id/franchise`는 `{ title, seasons, complete }`를 반환합니다. 시즌 항목에는 key/label/mediaId/provider/current와 확인된 season/part/seasonNumber/episodeCount 등이 포함됩니다. 회차가 미확인이면 episodeCount를 생략합니다.

같은 승인 TV ID나 정규화된 정확한 작품 제목을 연결 근거로 사용합니다. 서로 다른 승인 ID, 영화·극장판·특별편·재편집은 제외합니다. 승인된 숫자 시즌이 없는 자유형 부제·아크를 임의로 매핑하지 않습니다. 파이널 표기만으로 마지막 시즌 번호를 추측하지 않습니다. 로컬 다중 시즌은 실제 시즌 번호를 사용합니다.

전체 시즌으로 확인된 회차 수가 파트들을 충족할 때만 파트 행을 숨기며 현재 재생 중인 파트는 유지합니다. 가상 예: 시즌 3 전체 22회, 파트 1 12회, 파트 2 10회가 확인되면 전체 행을 대표로 쓸 수 있습니다. 회차 미확인 항목은 전체 판본의 증거가 아닙니다.

첫 응답은 알려진 DB 후보로 구성하고 필요하면 활성 소스를 백그라운드 검색합니다. `complete:false`는 탐색 중, true는 해당 탐색이 종료됐다는 뜻입니다. 모든 시즌·콘텐츠를 확보했다는 보장은 아닙니다. 후보와 현재 작품 모두 프로필의 키즈 정책을 다시 검사합니다. 수동 작품 그룹과 시즌 행의 정체성은 별개입니다.

## 소스 인기 목록

화면의 **오늘의 TOP 10**은 확장이 제공하는 인기 목록 순위를 합친 결과입니다. MOA 시청 통계나 실측 일간 순위는 아닙니다.

- 현재 탭의 주문형 소스별 인기 첫 페이지 최대 20개와 저장된 필터를 사용합니다. 추가 페이지는 요청하지 않습니다.
- 1~20위에 20~1점을 주고 기존 프로필별 작품 식별·시즌·판본·수동 묶기 규칙을 적용합니다. 소스 하나는 같은 그룹에 가장 높은 순위 한 번만 기여합니다.
- 총점, 기여 소스 수, 최고 순위, 안정적인 그룹 키 순으로 정렬합니다. 같은 입력은 응답 순서가 달라도 같은 결과를 만듭니다.
- 제공된 항목만 계산합니다. 관련 없는 로컬 복사본은 점수를 더하지 않으며 사용 중지·실시간·접근 불가·다른 공급자 항목은 제외합니다. 어린이 정책도 적용합니다.
- `POST /api/media/popular` 본문은 `{lists:[{sourceId,ids}]}`이며 최대 32소스×20 ID를 받아 최대 10개를 반환합니다. 클라이언트는 프로필·입력 목록별 5분 캐시합니다.
- 표시용 작품 묶기 설정과 별개로 같은 작품 순위를 합칩니다. 히어로·소스별 목록의 표시 설정은 유지합니다. 조회 실패 시 순위 행을 숨기며 가짜 순위를 만들지 않습니다.

## 캐시와 상태

소스 목록·검색·상세는 제한된 SQLite 캐시와 동일 요청 병합을 사용합니다. 유효한 결과를 재사용하고 만료 후 재사용이 허용된 결과는 먼저 반환한 뒤 갱신합니다. 완결 판단이 확실한 상세는 오래 보관하고 회차 변화가 관측되면 짧은 정책으로 돌아갑니다. 실패를 정상 결과처럼 영속 저장하지 않습니다.

이미지는 원 URL·헤더·크기 또는 로컬 파일의 변경 정보를 기준으로 WebP를 생성하고 디스크 LRU 예산을 적용합니다. 설치·설정·네트워크 변경은 관련 캐시를 무효화합니다. TTL·용량은 구현 상수이며 외부 서비스 이용 조건보다 우선하지 않습니다.

`GET /api/admin/cache-stats`는 관리자용 캐시 적중·미적중·외부 호출·자원 상태를 제공합니다. DB·운영 응답·개별 URL이 포함된 진단 출력은 비공개 경로에 둡니다. 공유 캐시는 계정 접근 권한과 키즈 정책을 대체하지 않습니다. 시청 기록·자막 선택·진행 중 세션은 캐시 삭제와 구분합니다.

## 프로필 추천

현재 프로필의 시청 기록과 내 목록에서 추천 근거를 고릅니다. TMDB가 설정되지 않았거나 근거가 없으면 추천 행을 표시하지 않습니다. 설정에서 추천을 끄거나 숨긴 추천을 초기화할 수 있고, 개별 후보는 관심 없음으로 제외합니다.

### 근거와 순위

- 최근 90일의 유효 시청 기록과 최근 추가한 내 목록을 사용합니다. 진행률은 마지막 위치·길이·완료 상태이며 실제 누적 시청 시간이나 명시적 평점이 아닙니다.
- 확인된 TMDB 종류·ID가 같으면 소스가 달라도 하나의 근거로 계산합니다. 실제 작품·회차 ID와 기록은 합치지 않습니다. 모호한 연결은 근거에서 제외합니다.
- 시청 기록 가중치는 1, 완료 기록은 1.25, 내 목록은 0.8이며 오래된 순서에 따라 줄어듭니다. 겹치는 근거는 큰 값에 작은 값의 20%만 더합니다. 내 목록을 좋아요나 완주로 해석하지 않습니다.
- 상위 근거 20작품의 기존 TMDB 추천 캐시에서 최대 100개 후보를 모아 장르 다양성을 고려하고 최대 40개를 반환합니다. 본 작품·내 목록·관심 없음은 매번 제외하고 프로필의 어린이 정책을 적용합니다.
- 빠진 근거 메타데이터는 최대 두 요청으로 백그라운드 보강합니다. 홈 응답을 기다리게 하거나 소스 목록 전체를 순회하지 않습니다. 캐시된 한국어 제목이 있으면 추천 제목과 근거에 사용합니다.

확인된 MOA 작품은 상세 화면으로, 외부 후보만 있으면 제목 검색으로 연결합니다. 추천에 나타났다는 이유로 설치한 소스에서 재생할 수 있다는 뜻은 아닙니다. 기록·내 목록·연결·관심 없음·프로필 정책의 변경은 다음 요청에 반영합니다.

### 선택적 AniList 보강

`anilistRecommendationsEnabled`는 프로필별 기본 꺼짐입니다. TMDB가 설정돼 있고 추천이 40개 미만이며 애니 후보가 12개 미만일 때만 보강합니다. 어린이 프로필에는 적용하지 않습니다. 기존 TMDB 순서를 유지하며 AniList 커뮤니티 점수를 TMDB 점수에 합산하지 않습니다.

확정된 TMDB 근거 중 원제·연도·애니 장르가 있고 특정 후속 시즌 연결이 아닌 최대 세 작품을 조회합니다. AniList의 제목·연도·TV/영화 형식이 정확히 맞는 단일 후보만 사용합니다. 추천도 다시 TMDB의 원제·연도·장르·형식으로 확인하며 시즌·파트를 지우거나 애매한 OVA·후속 시즌을 강제로 연결하지 않습니다. 기존 MOA/TMDB ID와 기록은 유지합니다.

외부에는 필요한 공개 작품명·연도·형식만 보냅니다. 프로필 ID·시청 위치·계정·소스 주소·전체 개인 목록은 보내지 않습니다. 고정된 읽기 전용 GraphQL 요청과 제한된 캐시를 사용합니다. AniList 요청 한도와 429 대기는 리뷰 기능과 공유하고, 장애나 보강 결과 없음은 기존 TMDB 추천을 중단하지 않습니다. 계정 동기화나 평점 쓰기는 제공하지 않습니다.

### API와 플러그인

`GET /api/recommendations`는 인증된 현재 프로필의 결과만 반환합니다. `disabled`, `unconfigured`, `insufficient-history`, `ready`를 구분하며, `insufficient-history`는 시청 기록과 내 목록 모두에서 근거를 얻지 못한 상태입니다.

내장 추천과 플러그인은 기록 조회 계층을 공유합니다. 플러그인에는 명시적 `history.read` 또는 `watchlist.read` 권한이 필요하며 추천 설정만으로 권한을 부여하지 않습니다. 페이지 조회·설치 revision·프로필 잠금과 외부 전송 경계는 [플러그인 계약](PLUGINS.md)을 따릅니다.

추천 품질·공급자 수록률과 판본 매칭에는 한계가 있습니다. 외부 API의 [AniList 이용 조건](https://docs.anilist.co/guide/terms-of-use)을 준수하며, 작품 기반 추천을 전체 서비스의 시청 통계로 표현하지 않습니다.

## 쇼츠

프로필에서 직접 켜는 예고편 탐색 기능입니다. TMDB의 Trailer·Teaser 정보와 YouTube 공식 플레이어를 사용하며 전체 회차를 잘라 보여주지 않습니다. 기존 예고편·회차 재생·다운로드·추천과 별도로 동작합니다.

### 설정과 후보

- `shortsEnabled`: 기본 꺼짐입니다. 끄면 후보를 조회하지 않습니다. 공개 인기 정보만으로 등급을 확인하기 어려워 어린이 프로필에는 제공하지 않습니다.
- 분류는 영화·시리즈·애니메이션이며 기본 모두 선택, 최소 하나 선택입니다. 애니는 TMDB 장르 16을 사용하며 뉴스·리얼리티·토크는 시리즈에서 제외합니다. 스포츠·예능·장르 미상은 추측해 분류하지 않습니다. 기존 장르 없는 기록은 정상 정보 갱신 후 사용할 수 있습니다.
- 인기 후보는 분류별 TMDB 인기 첫 페이지 최대 20개이며 애니는 영화·TV를 섞습니다. 공개 목록 3개는 30분 캐시하고 같은 요청을 합칩니다. 실패는 1분 후 재시도하며 영상 소스 목록을 수집하지 않습니다.
- `shortsMode`: `mixed`(기본), `personal`, `popular`입니다. 혼합은 개인 추천 최대 2개와 인기 1개를 섞고 남은 후보를 사용합니다. 개인 후보가 없으면 인기 후보로 이어지며 추천 거부·관심 없음을 존중합니다.
- `shortsHideWatched`: 기본 true이며 회차 진행 기록이 있는 작품을 제외합니다. 기록을 지우지는 않습니다. 개인 추천은 이미 본 작품을 제외하므로 해제 시 주로 인기 후보에 적용됩니다.
- `shortsRepeatDays`: 기본 7일, 선택값 0·1·7·30일입니다. 0은 반복 제외를 끕니다. 실제 재생 5초 또는 직접 다음으로 넘긴 작품은 프로필·TMDB 작품별로 제외합니다. 자동 전환·재생 실패·배경 이동은 넘김 신호가 아니며 같은 작품의 영상만 바꿔도 반복 제한을 피하지 못합니다. 영구적인 싫어요나 회차 시청 기록으로 취급하지 않습니다.
- 재생 불가 예고편은 반복 기간(최소 1일), 일시적 연결·플레이어 오류는 1시간 제외합니다. 다시 보기에도 적용하며 쇼츠 기록 초기화 시 함께 지웁니다. 미리 준비한 영상의 실패는 실제 열었을 때만 기록하고 자동재생 차단은 실패로 보지 않습니다.
- 후보는 개인 최대 40개·인기 60개이며 `(kind, TMDB id)`로 중복을 제거합니다. 인기 순서는 프로필·날짜별로 안정적이며 페이지당 최대 8개입니다. `replay=1`은 해당 요청에서 예고편 시청 제외만 건너뛰고 본 회차·관심 없음은 유지합니다. 후보가 없으면 빈 화면을 안내하며 임의로 반복하지 않습니다.

연결된 작품은 MOA 상세, 외부 작품은 내부 검색으로 엽니다. 설치한 소스에 영상이 있다는 보장은 아닙니다.

### 화면과 조작

`shortsScreenFit`은 기기·프로필별 설정이며 null은 자동입니다. 터치 기기는 채우기, 데스크톱은 전체 표시를 기본으로 사용합니다. 예전 프로필의 명시적 꺼짐은 기기 선택 전까지 유지하지만 예전 기본 켜짐으로 데스크톱을 강제 확대하지 않습니다.

YouTube 방식은 가로 영상과 조작부를 자르거나 덮지 않습니다. 모바일에서는 화면 안에서 비율을 유지하고 주변은 앱 배경을 사용합니다. 세부 화면 맞춤은 YouTube가 처리합니다. 이동 동작은 주변 영역에서 하고 명시적 이동 버튼도 제공합니다. 활성 플레이어는 하나이며 작품 변경·화면 숨김·종료 시 중지합니다. 자동재생 차단은 터치를 요청하고, 영상별 실패만 다른 후보로 바꿉니다. 네트워크/API 실패로 끝없이 다음 작품으로 넘어가지 않습니다.

### API

계정 소유권·프로필·PIN 검사를 적용하며 응답은 `private, no-store`입니다.

| 요청 | 동작 |
| --- | --- |
| `GET /api/shorts?cursor=…&replay=1` | `ShortsFeed`. 필터링된 페이지가 아닌 원래 후보 목록을 기준으로 이동합니다. 정보 변경에 대비해 클라이언트도 중복을 제거합니다. |
| `GET /api/shorts/:key/trailers` | `{trailers,checked}`. 현재 작품만 조회하고 동시 4개·같은 요청 병합·6시간/최대 256개 캐시를 적용합니다. 설정 변경 시 초기화합니다. 선택적 YouTube 사전 검사 실패는 일반 플레이어의 후보 전환을 유지합니다. |
| `POST /api/shorts/:key/seen` | `{ok:true}`. 화면에 보이는 실제 재생 5초 뒤 한 번 기록합니다. 시각은 서버 기준이며 프로필별 최근 2,000개·30일 만료입니다. |
| `POST /api/shorts/:key/skip` | `{ok:true}`. 현재 표시된 작품에서 사용자가 직접 앞으로 넘길 때 한 번 기록합니다. 빠르게 지나간 미표시 카드는 제외하지 않습니다. |
| `DELETE /api/shorts/seen` | 해당 프로필의 쇼츠 시청 제외 기록만 초기화합니다. |
| `GET/PATCH /api/settings` | 프로필 설정입니다. 화면 맞춤은 기기 ID를 사용하는 `/api/settings/device`에 저장합니다. |

조회만으로 재생 성공이나 전체 회차 시청을 기록하지 않습니다. 이 기록은 취향 신호이며 검증된 시청 통계가 아닙니다.

### 직접 재생 실험 기능

추출기가 설정된 새 프로필은 `native`, 기존 프로필은 저장된 선택(예전 기본 `embed`)을 유지합니다. 직접 재생은 MOA 영상 요소를 사용합니다. 모바일 채우기는 영상만 `object-fit: cover`로 자르며 끄면 전체 프레임을 표시합니다. 두 손가락을 안으로 모으면 전체 표시, 밖으로 벌리면 채우기로 바꾸고 현재 기기에만 저장합니다. 한 손가락 이동과 길게 눌러 배속은 별개입니다. 영상 위 조작부·자막은 직접 재생에서만 표시합니다.

서버의 `MOA_SHORTS_EXTRACTOR`에 EJS가 포함된 yt-dlp 실행 파일을 지정해야 하며 JS 실행에는 Node 22 이상이 필요합니다. 기본 이미지의 경로는 `/usr/local/bin/yt-dlp`이며 빈 값으로 끌 수 있습니다. `GET /api/shorts/native`는 설정 여부이고 YouTube 요청 성공 보장은 아닙니다. 프로필의 기능 사용과 재생 방식은 별도로 선택합니다.

현재 작품의 기존 TMDB/YouTube 후보 최대 2개만 확인합니다. 클라이언트가 영상 URL을 지정할 수 없으며 고정 YouTube 주소·사용자 설정/플러그인 무시·로그인 쿠키 없음·실행 중 구성요소 다운로드 없음 원칙을 지킵니다. 서버 기본 프록시의 같은 설정으로 추출과 중계를 수행합니다.

허용 영상은 실시간·DRM이 아닌 10분 이하 H.264/AAC MP4 또는 HLS, 최대 720p입니다. 분리 HLS는 마스터 목록의 호환 영상과 대응 음성을 함께 유지합니다. 영상 전용 목록을 완전한 영상으로 취급하지 않습니다. 사용할 HLS 마스터가 없는 분리 MP4/WebM은 지원하지 않으며 변환·전체 파일 다운로드를 하지 않습니다.

| 요청 | 동작 |
| --- | --- |
| `POST /api/shorts/:key/native {}` | `{sessionId,url,mime,subtitles}`. 원본 서명 URL 대신 같은 출처의 임시 세션 URL을 반환합니다. |
| `GET /api/playback/:sessionId/shorts/:assetId` | 계정·PIN·시청 권한, 공개 IP·DNS 고정, 이동 경로를 검증합니다. HLS 자산은 같은 세션으로 연결하며 암호화 목록은 거부합니다. |
| `DELETE /api/shorts/native/:sessionId` | 현재 프로필 소유 세션을 해제합니다. 카드 종료 시 준비 요청도 취소합니다. |
| `POST /api/shorts/native/:sessionId/warm` | 현재 영상 재생 시작 후 다음 두 작품을 순서대로 미리 준비합니다. |

추출은 동시 2개·후보당 40초이며 취소·만료·종료 시 자식 프로세스 그룹을 종료합니다. 세션은 프로필별 3개(현재+다음 2개), 전체 32개, 10분 만료입니다. 세션당 미디어 요청 동시 8개·총 128MiB·HLS 자산 1,024개·목록당 512KiB입니다. 성공한 후보는 프로필·후보 목록·프록시별로 2분/최대 64개 보관하고 원격 HTTP 실패 시 지웁니다. 모두 메모리에만 보관하며 준비·유효 세션은 업데이터의 진행 중 작업에 포함합니다.

#### 미리 준비와 자막

다음 두 작품은 첫 추출이 끝난 뒤 다음 추출을 시작합니다. 실제 재생·시청 기록을 만들지 않으며 이동 시 같은 요청·세션을 이어 씁니다. 화면 숨김·종료·후보 변경 시 취소하고 필요 없는 세션을 해제합니다. 실패한 미리 준비를 자동 반복하지 않습니다.

선택 화질(자동 시작은 360p)의 목록·초기화 데이터·6초분 또는 트랙당 3조각까지만 받습니다. MP4는 앞부분 512KiB입니다. 음성·영상은 병렬, 각 트랙의 조각은 순서대로 처리합니다. 준비 동시 2개·HTTP 동시 4개·12초·시도당 8MiB·조각당 2MiB·전체 캐시 32MiB로 제한합니다. 재생에서 재사용하며 자동 화질은 이후 720p까지 조정할 수 있습니다.

원본 VTT·원본 자동 자막을 가져오며 음성 인식은 하지 않습니다. 자막은 세션 전용 주소로 제공하고 트랙당 1MiB·동시 4개·세션당 4MiB·전체 16MiB로 제한합니다. 기존 번역 설정·권한·공유 대기열·요청 간격·캐시를 사용하되 현재 작품만 번역하고 미리 번역하지 않습니다. 회차·시청 기록·영구 자막 연결을 만들지 않으며 세션 종료 시 해당 번역 구독을 취소합니다.

직접 재생은 터치·키보드 탐색, 자막 선택, 길게 눌러 임시 2배속을 지원합니다. 제스처 종료·취소 시 원래 배속으로 돌아갑니다. 화질은 프로필 쇼츠 설정의 자동·360p·480p·720p이며 제한 이하 최고 화질 또는 가능한 최저 화질을 고릅니다. 단일 MP4·브라우저 기본 HLS는 Hls.js 화질 선택을 제공하지 않습니다. YouTube 방식은 자체 조작부를 사용합니다.

추출은 YouTube 변경이나 추가 토큰 요구로 실패할 수 있습니다. 계정 쿠키·PO 토큰 자동 발급은 제공하지 않습니다. 실패하면 기존 YouTube 방식으로 전환할 수 있으며 시청·싫어요로 기록하지 않습니다.

#### 이전 베타 이미지

beta.2·beta.3은 별도 실험 이미지가 필요할 수 있습니다. 고정 의존성은 yt-dlp `2026.08.19`와 EJS `0.8.0`입니다. 최신 기본 이미지는 같은 도구를 포함합니다.

```sh
docker build -t moa:shorts-native-base .
docker build -f deploy/shorts-native/Dockerfile -t moa:shorts-native-trial .
```

실험은 별도 데이터·포트로 실행하고 `MOA_SHORTS_EXTRACTOR=/usr/local/bin/yt-dlp`를 명시합니다. Compose의 빈 값은 이미지 ENV보다 우선합니다. 이미지 교체만으로 기존 프로필 방식이 바뀌지는 않습니다. 추출기 제거 시 YouTube 방식을 유지하며 별도 데이터 이관은 필요하지 않습니다.
