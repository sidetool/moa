# 다음 버전 구현 계획

작성: 2026-10-11. 기준: v0.1.1. 상태: 사용자와 합의한 개발 범위의 설계, 구현·배포 전.
버전 후보는 v0.2.0-beta.1 → 베타 검증 → v0.2.0이다. 실제 번호는 구현 완료 시 결정하며 이 문서만으로 태그를 발행하지 않는다.

## 1. 범위와 원칙

다음 버전의 핵심 기능은 세 가지다.

1. 프로필의 시청기록을 활용하는 내장 추천.
2. 영화·드라마의 오프닝/엔딩·크레딧 구간 조회와 건너뛰기.
3. 확장 소스 영상을 MOA 서버에 저장하고 기존 플레이어에서 재생.

완전 오프라인 웹앱/PWA, 기기 내부 영상 보관·기록 동기화는 구현하지 않는다. 서버 저장은 클라이언트가 MOA 서버에 접속해야 하는 기능이다. 기기로 파일 내보내기도 이번 필수 범위에서 제외한다.

일정표·인기·성우/제작진 등 플러그인은 [별도 후보 계획](PLUGIN-CANDIDATES.md)에 둔다. 추천은 내장 기능으로 제공하되, 명시적으로 허용된 플러그인을 위한 읽기 전용 시청기록 계약도 공통 조회 계층으로 설계한다.

- 기존 재생, JS/APK 확장 계약, 작품·회차 ID, 프로필 기록을 유지한다. 확장마다 별도 설정이나 구현을 요구하지 않는다.
- 외부 서비스 장애·일치 정보 없음·저장 기능 미설정은 기존 기능 실패로 이어지지 않는다.
- 기존 설치에서 기능을 사용하지 않을 때 추가 브라우저나 분석 프로세스를 상시 실행하지 않는다.
- 공용 코드·테스트·문서에는 사이트 전용 식별자와 인증 정보를 넣지 않는다. 실사이트 자료는 비공개 확장 폴더에서만 관리한다.
- 구현은 별도 브랜치/기능별 PR로 진행한다. UI는 사용자 지정 Opus 5.5 작업자에게 목표·데이터·상태 계약을 전달하고 디자인 판단은 맡긴다.

## 3. 내장 시청기록 추천

### 사용 흐름

홈에 프로필별 추천 행을 표시한다. 충분한 기록이 있으면 “이 작품을 보셔서 추천” 같은 근거를 제공한다. 기록이 없거나 TMDB가 미설정이면 빈 행을 숨긴다. 외부 인기 목록을 사용할 경우 개인 추천으로 오인하지 않게 별도 표시한다.

설정에서 추천 표시를 끌 수 있고, 후보별 ‘관심 없음’과 숨긴 추천 초기화를 제공한다. 초기에는 사용자의 명시적 점수 입력이나 학습 모델을 요구하지 않는다.

### 데이터 흐름

1. 현재 프로필의 최근 기록을 조회한다. 초안 상한: 최근 90일, 작품 20개. 현재 progress는 누적 시청 시간이 아니라 마지막 위치·길이·완료 플래그다. 초기에는 위치/완료 신호를 약한 선호 근거로 쓰고 시작 직후의 기록을 걸러낸다. 끝으로 seek한 기록까지 실제 시청과 구분한다고 주장하지 않는다. 정확한 누적 시청량 수집은 이번 범위가 아니다.
2. 회차 기록을 작품 단위로 요약한다. 다수 회차를 본 한 작품이 추천 전체를 독점하지 않게 기여도를 제한한다.
3. 확정된 `(TMDB 종류, TMDB ID)`가 같으면 다른 소스의 같은 작품을 추천 계산에서만 중복 제거한다. 실제 작품·회차 ID와 기록은 합치거나 변경하지 않는다. 매칭이 없거나 모호하면 후보 생성의 근거에서 제외한다.
4. 기존 TMDB 상세의 `similar`/recommendations 캐시를 먼저 사용한다. 누락 시 상위 근거 작품 소수만 보강한다. 초안: 한 번에 최대 5작품, 동시 요청 2개, 후보 100개. 매 홈 진입 때 전체 기록을 조회하거나 소스를 순회하지 않는다.
5. 최근성·완료 신호·여러 근거 작품의 공통 추천을 가중하고 장르 다양성을 확보한다. 근거를 설명할 수 있는 점수로 시작하며 AI 서버는 두지 않는다.
6. 이미 본 작품·숨긴 후보·잘못 연결된 항목을 제외한다. 프로필/키즈 제한은 근거와 결과 양쪽에 적용한다. 등급 미상 처리도 기존 키즈 정책을 따른다.
7. MOA의 확인된 작품에 연결할 수 있으면 상세로, 외부 후보만 있으면 제목 검색으로 이동한다. TMDB 후보가 있다는 이유로 ‘재생 가능’이라고 표시하지 않는다.

### 구현 단위

- 서버 `recommendations.ts` 서비스와 프로필 인증이 적용되는 조회/제외 API.
- 공용 `RecommendationCandidate`: 외부 작품 키, 표시 정보, 추천 이유, 선택적인 MOA 작품 참조, 상세 또는 검색 목적지. 영상 URL·비밀키를 포함하지 않는다.
- `recommendation_feedback(profile_id, provider, kind, external_id, action, updated_at)` 등의 가산 테이블. 제외/취소는 멱등 처리.
- TV 중복 제거는 시리즈 단위라는 첫 버전 정책을 명시한다. 한 시즌을 봤다고 모든 시즌을 완주했다고 표시하지 않는다. 다음 시즌 안내는 개인 추천과 별도 후속 기능이다.
- `similar` 캐시 항목에는 키즈 판단에 필요한 상세 등급이 충분하지 않다. 외부 후보는 `KidsPolicy.candidates`와 같은 검증을 거치며, 미확인 후보는 숨긴다. 후보 전체의 상세를 한 번에 요청하지 않는다. MOA 작품 연결도 실제 조회/재생 시 권한을 재검사한다.
- 캐시는 프로필·기록 revision·제외 revision·TMDB 연결 revision·키즈 정책을 구분한다. 기록 삭제/초기화·프로필 변경·매칭 정정 시 이전 추천 근거가 남지 않게 무효화한다.
- 추천 계산과 TMDB 보강은 홈의 기존 응답/재생을 막지 않는다. 짧은 메모리 계산과 캐시를 우선하며 외부 API 실패는 해당 행에만 영향.
- 계정/프로필 ID나 전체 시청기록을 외부로 전송하지 않는다. 외부 조회에는 필요한 작품 ID만 사용한다.

### 완료 조건

프로필/키즈 격리, 같은 작품의 다중 소스 중복 제거, 시작 직후 위치의 기록 제외, 관심 없음/취소, 기록 삭제 후 캐시 갱신, TMDB 장애 시 홈 정상 동작. 오래된 기록·모호한 매칭에 추천 이유를 붙이지 않는다.

### 추가 합의: 플러그인용 읽기 전용 기록 API

내장 추천과 플러그인은 공통 시청기록 조회 서비스를 사용한다. 추천 알고리즘의 점수·기간 정책을 플러그인에 강제하지 않는다. 아래 이름은 구현 계약 초안이며 기존 플러그인 API 1/2는 그대로 유지한다.

- 명시적 `history.read` 권한으로 `moa.history.list({ cursor?, limit?, since? })`를 제공한다. 기본 50개, 최대 100개의 cursor 페이지 조회로 제한한다. 업데이트로 새 권한이 추가되면 기존 설치에 자동 승인하지 않는다.
- 프로필은 호출자가 임의로 전달하지 않고 현재 인증된 프로필로 결정한다. 서버에서 설치 상태·패키지 revision·권한·프로필 소유권과 잠금·키즈 정책을 매번 검사한다.
- 레코드는 기존 media/episode ID, 표시 제목, 시즌·회차, 마지막 위치·영상 길이·완료 여부·갱신 시각, 확인된 TMDB kind/id를 제공한다. 실제 누적 시청시간으로 표현하지 않는다. URL·헤더·쿠키·계정 정보·API 키는 제공하지 않는다.
- 작품별 요약은 원시 회차 기록과 분리된 조회로 정의한다. 이때도 기존 작품 ID나 사용자 기록을 합치지 않는다. 페이지 순서는 갱신 시각과 안정적인 ID로 결정한다.
- 기록 변경 revision을 응답에 포함하여 플러그인이 캐시를 갱신할 수 있게 한다. 기록 삭제·프로필 전환 후 이전 데이터가 호스트 캐시에 남지 않게 한다. 이미 플러그인이 복사한 기록까지 회수할 수 있다고 보장하지 않는다.
- 설치 권한 안내에는 시청기록 접근임을 명시한다. 외부 통신 권한도 가진 플러그인은 읽은 기록을 전송할 수 있으므로, URL을 숨기는 것과 기록 유출 방지는 구분한다.
- 기록 쓰기·삭제 API, 전체 프로필 조회, 추천 알고리즘 등록 체계는 이번 범위에 추가하지 않는다. 일반 플러그인의 홈 배치와 기존 UI 기능으로 추천을 표시할 수 있다.
- 구현 시 프로필 격리, 권한 미승인/회수, 페이지 제한, 기록 삭제 후 조회를 필수 확인한다.

## 4. 영화·드라마 구간 건너뛰기

### 지원 계약

AniSkip 경로와 수동 구간을 유지하면서 일반 영상 공급자 하나를 추가한다. 외부 조회가 불가능하면 구간 없음으로 처리한다. 최초 지원은 확인된 구간의 버튼 표시이며, 엔딩 자동 다음 회차 이동이나 쿠키영상 자동 건너뛰기를 새 기본값으로 만들지 않는다.

공급자는 IntroDB (`introdb.app`) 또는 TheIntroDB (`theintrodb.org`)를 후보로 두되 서로 다른 서비스로 구분한다. 공식 API의 지원 ID, 영화/TV 구분, 판본/길이 정보, 출처 표시, 제한, 캐시 조건과 실제 표본을 비교한 뒤 하나를 선택한다. 모든 한국 작품의 지원을 보장하지 않는다.

### 처리 흐름

1. 이미 연결된 외부 작품 ID와 확정된 시즌·회차로 조회한다. 시즌 통합 작품, 특집/합본 회차가 모호하면 생략한다. 영화는 TV의 임의 시즌/회차로 조회하지 않는다.
2. 실제 플레이어의 재생 길이를 사용한다. 외부 구간을 얻으려고 영상 길이를 다른 값으로 위장하거나 카탈로그 추정 길이로 대체하지 않는다.
3. 공급자 응답을 공통 모델로 변환한다. 단위(ms/sec), intro/credits/recap/post-credits 등을 명시적으로 매핑한다. recap과 쿠키영상은 이번 표시 대상이 아니면 무시한다.
4. 시작/끝·순서·길이·영상 경계를 검증한다. 판본/길이/신뢰도 정보가 있으면 함께 비교한다. 허용 오차는 실제 표본 근거로 정하며, 길이가 비슷하다는 이유만으로 같은 편집본이라고 간주하지 않는다.
5. 판본을 검증할 근거가 없는 공급자는 자동 적용 대상으로 채택하지 않는다. 명시적 사용자 선택이 필요한 제한적 결과로 분리하거나 첫 버전에서 제외한다. 이것이 공급자 선택의 완료 조건이다.
6. 실제 스트림/파일 판본별로 캐시한다. 작품 ID만 같다고 다른 영상에 구간을 복사하지 않는다. 성공/정보 없음/요청 실패의 캐시 시간을 구분한다.
7. 기존 마커 병합에 출처와 판본 정보를 추가한다. 우선순위 초안은 같은 판본의 수동 지정 > 검증된 로컬 분석 > 외부 조회. 부분 결과와 일시적 실패가 이미 확인된 다른 구간을 지우지 않게 한다.

### 코드와 범위

- 현재 `remoteMarkers`는 source 연결 회차만 조회하며 anime로 제한한다. 타입 조건만 확장하면 로컬 영화에는 적용되지 않는다. 권한이 확인된 공통 회차/작품 조회와 실제 재생 세션의 길이·판본을 입력으로 받아 로컬/원격 양쪽에 연결한다.
- 요청은 `episodeId`뿐 아니라 해당 프로필의 실제 재생 세션에 묶고, 응답에 session/generation을 대응시킨다. 안정적인 판본 키가 없는 원격 영상은 세션 범위로만 캐시해 다른 서버·화질 선택에 그대로 사용하지 않는다. 서명 URL 자체나 표시용 화질 이름을 영구 판본 키로 삼지 않는다.

- `packages/skip-markers`: 공급자 어댑터, 정규화/검증, provenance 타입 확장.
- `tmdb.ts`: 필요하다면 외부 ID 조회를 기존 키 관리/캐시에 포함.
- `enrichment.ts`: anime/movie/series별 적절한 조회, 제한된 동시성·취소·캐시.
- `WatchPage.tsx`: v0.1.1의 세션별 마커 보존을 유지; 이전 세션 응답 혼입 방지.
- 로컬 시리즈 분석은 기존 코드 활용. 영화 크레딧 OCR, 무작위 원격 회차 다수 다운로드, 상시 영상 분석은 이번에 추가하지 않는다.
- `creditsEnd`가 있으면 그 위치까지 이동한다. 끝을 모른다고 무조건 영상 끝/다음 회차로 보내지 않는다.

### 완료 조건

합성 응답으로 단위·잘못된 회차·길이 불일치·부분 구간·타임아웃·세션 교체를 확인한다. 실제 영화/드라마 소수의 서로 다른 판본에서 위치와 쿠키영상 보존을 확인한다. 데이터가 없는 작품은 정상적인 ‘구간 없음’이며 재생 실패가 아니다.

## 5. 소스 영상 서버 저장

### 첫 버전 사용 흐름

작품의 회차에서 ‘서버에 저장’을 선택하고 이용 가능한 화질/서버를 고른다. 작업 목록에서 대기·저장 중·완료·실패를 확인하고 취소/재시도를 한다. 완료 후 같은 회차를 열면 저장본을 우선 사용하고, 원본 소스로 재생하는 선택도 제공한다.

작품 전체 자동 수집, 신작 구독 다운로드, PWA 오프라인, 클라이언트 파일 저장은 제외한다. 첫 버전은 단일 회차 요청을 큐에 넣는 흐름으로 범위를 제한한다.

### 지원 포맷

- 첫 대상: DRM 없는 유한 길이 MP4와 일반 HLS VOD.
- 라이브·DASH·DRM·대화형 인증이 반복적으로 필요한 스트림은 첫 버전에서 명확하게 미지원 처리한다.
- HLS는 확정된 variant와 필요한 오디오/자막 트랙을 선택하고 상대 URL·초기화 세그먼트·타임라인을 처리한다. 일반 AES-128 HLS는 키/IV와 키 URL의 기존 네트워크 정책을 지키며 지원 가능성을 확인한다. SAMPLE-AES/DRM이나 모호한 암호화는 실패 사유를 표시한다.
- 초기에는 선택한 화질·오디오 한 조합과 확보 가능한 선택 자막을 저장한다. 자막 수신 실패는 영상 ready와 별도로 표시한다. 기존 프로필별 자막 선택/번역 자막을 전체 사용자 공용 기본값으로 바꾸지 않는다. 전체 트랙 자동 보관·재인코딩은 하지 않는다.
- 가능하면 코덱 복사로 컨테이너를 정리한다. 재생 기기가 코덱을 지원하지 않을 때만 기존 재생 트랜스코딩 정책을 따른다.

### ID와 자산 모델

`download_jobs`와 `download_assets`를 별도 테이블로 둔다. 파일명이나 URL을 새로운 회차 ID로 삼지 않는다.

- job: 요청자/프로필, 기존 source/media/episode ID, 선택한 품질·트랙, 상태·진행·재시도, 시간, 정리 대상 상대 경로.
- asset: 기존 episode ID, 저장 루트 내 상대 경로, 크기·파일 검증 정보·재생 probe, 자막 참조, 판본/길이, 완료 시각.
- 소스 주소 변경 후에도 ID alias 해석을 사용한다. 제목 유사성만으로 연결하지 않는다.
- 일반 폴더 스캐너가 저장 디렉터리를 다시 등록해 작품·회차를 중복 생성하지 않도록 한다.
- `POST /api/playback`은 현재 source 회차를 원격 재생으로 먼저 보낸다. 이를 명시적 재생 위치 선택(`auto/saved/source`)으로 연결한다. `auto`는 ready 저장본 우선이며, 소스 사이트가 내려가도 저장본 재생을 위해 원격 상세/영상 추출부터 호출하지 않는다. 파일이 사라진 경우에만 상태를 missing으로 정리하고 원격 경로를 안내/사용한다. 권한 거부를 원격 fallback으로 우회하지 않는다.
- 저장 자산 resolver를 두고 기존 로컬 플레이어에 검증된 파일/probe를 제공하는 안을 우선한다. 현재 `Playback`은 생성·세그먼트 처리에서 `/media` 기준 safePath를 재검사한다. 재생 세션에 서버가 선택한 저장 루트 종류를 보관하고 `/downloads`에도 동일 검사를 적용한다. 클라이언트가 임의 경로/루트를 지정할 수 없게 한다. 기존 files/스캐너의 소유권은 유지한다.
- 저장본 삭제는 저장 파일/자산만 지우고 작품·시청기록·찜을 지우지 않는다.
- 확장 제거/작품 정리 시 기존 cascade가 저장본과 기록을 날리지 않도록 보호한다. 첫 버전은 완료 자산 또는 대기/실행 작업이 있는 소스/작품의 파괴적 제거를 막고 저장본을 먼저 정리하도록 안내하는 계약을 우선한다. 확장 업데이트·도메인 변경은 기존대로 허용한다.

### 작업자·네트워크

- 초기 동시 다운로드 1개. 앱 내 큐 조정 + 작업 중에만 자식 프로세스. 별도 상주 브라우저/다운로드 데몬을 추가하지 않는다.
- 작업 상태는 queued → resolving → downloading → finalizing → ready이며, failed/cancelled/interrupted에서만 명시적으로 재시도한다. 중복 클릭은 멱등 키와 회차별 작업 제한으로 합친다. 첫 버전은 회차당 ready 저장본 1개이며, 기존 파일을 몰래 덮어쓰지 않고 다른 품질 저장은 기존 저장본 정리 후 진행한다. 저장본 재생 중 삭제는 막고 종료 후 다시 요청하도록 한다.
- 일반 재생 세션의 수명에 매달리지 않는 작업용 요청 수명·취소·인증 갱신을 둔다. JS/APK가 기존 방식으로 반환한 Video 목록을 소비하고 별도 다운로드 API를 확장에 요구하지 않는다.
- 기존 소스별 프록시, 헤더의 origin 범위, 주소/리다이렉트 검사, 브라우저 인증 세션을 재사용한다. 영상 링크를 ffmpeg에 직접 전달하여 HTTP 정책을 우회하지 않는다. 기존 통제된 전송 경로 또는 검증된 로컬 중계를 쓴다.
- APK의 `apkLease`가 있는 영상은 다운로드가 lease를 소유하고 필요 시 갱신하며 완료/실패/취소에 해제한다. JS 추출 URL과 같다고 가정하지 않는다. data HLS·EDL 등 내부 스트림 형식도 기존 해석 경로를 확인한다. 안전하게 처리할 수 없는 형식은 저장만 미지원으로 표시하고 기존 재생은 유지한다.
- Signed URL·쿠키·인증 헤더를 DB 작업 필드나 로그에 오래 보관하지 않는다. 재시도 시 원래 회차에서 영상 주소를 다시 구한다.
- URL 갱신 후 다른 파일을 이어 붙이지 않는다. MP4 Range 재개는 서버의 Range 지원과 strong ETag 등 신뢰할 수 있는 동일 파일 근거가 있을 때만 한다. HLS의 임의 세그먼트 이어받기는 첫 버전 필수 기능이 아니며 불확실하면 해당 임시 작업을 처음부터 다시 받는다. URL/파일명/크기만 같은 것은 재개 근거로 충분하지 않다.
- 완료는 `.part`에 수신 → 미디어/크기 검증 → 같은 파일시스템에서 원자적 이름 변경 → DB ready 등록 순서다. 중간 종료 시 고아 파일/DB 상태를 시작 시 조정한다.
- 재시도는 제한하고 인증 실패·지원 불가·용량 부족을 구분한다. 실패를 무한 재시도로 숨기지 않는다.

### 저장소·권한·업데이트

- 전용 `/downloads` 영속 마운트와 별도 설정 사용. 기존 `/media`의 읽기 전용 정책을 바꾸지 않는다.
- 마운트·쓰기 가능 여부·관리자 저장 한도 설정 전에는 다운로드 기능을 비활성화하고 이유를 보여준다. 기존 설치는 자동으로 대용량 파일을 받지 않는다.
- 전체 한도·남은 디스크 최소 여유·작업별 상한을 시작 전과 수신 중 모두 검사한다. 완료 파일을 임의로 자동 삭제하지 않는다.
- 첫 버전의 저장/삭제 관리 권한은 관리자에게 한정한다. 저장본 재생은 기존 프로필 접근·키즈 제한을 그대로 적용한다. 이후 필요하면 회원 다운로드 권한을 별도로 추가한다.
- 저장 파일은 정적 URL로 공개하지 않는다. 정상 재생 인증을 거친다. 안전한 루트·심볼릭 링크·삭제 대상 검사도 기존 파일 정책을 유지한다.
- 현재 업데이터는 `/data` 전체를 백업하므로 영상 본체를 `/data`에 두지 않는다. 작업 메타데이터는 백업하되 다운로드 영상은 유지되는 별도 볼륨이다. 메타데이터 복구 후 파일 재조정이 가능해야 한다.
- Compose뿐 아니라 릴리스 설치기와 업데이터의 서비스 마운트 처리도 수정한다. 기존 release compose가 새 마운트를 자동으로 얻는다고 가정하지 않는다. 업데이트 시 비활성 상태를 유지하고, 관리자에게 1회 저장 폴더 설정 경로를 제공한다.
- 유지보수 진입 시 새 다운로드 시작을 막고 현재 작업을 중단 가능한 상태로 정리한다. 현재 업데이터의 busy 검사/lease 순서를 먼저 확인해, 다운로드가 busy이므로 lease를 못 받고 lease가 없어 다운로드도 멈추지 않는 교착을 피한다. 사용자가 누른 업데이트 요청에서 먼저 큐 시작을 중지하고 현재 전송·자식 작업을 bounded drain한 뒤 설치를 허용하는 준비 단계를 연결한다. 업데이트 취소/실패 시 새 작업 접수 중지를 해제한다. 대형 다운로드 때문에 업데이트가 영원히 기다리지 않게 한다. 재시작 후 작업은 interrupted 상태로 복원하고 사용자가 재시도한다.

### API 경계 초안

| 경로 | 계약 |
| --- | --- |
| `GET /api/recommendations` | 서버가 인증한 현재 프로필의 후보/근거만 조회 |
| `PUT/DELETE /api/recommendations/dismissals/:key` | 검증된 외부 작품 키의 관심 없음 설정/취소; 임의 프로필 ID 불허 |
| `GET/POST /api/admin/downloads` | 작업 목록/기존 회차와 검증된 선택으로 저장 요청; 임의 URL/경로 불허 |
| `POST /api/admin/downloads/:id/cancel` 및 `/retry` | 상태 전이 검증, 반복 호출 멱등성 |
| `DELETE /api/admin/download-assets/:id` | 저장 자산만 정리, 사용 중 파일 보호 |
| 기존 playback/markers API | 저장 위치 선택과 세션별 구간 계약 확장, 현재 권한 검사 유지 |

실제 라우트 이름은 기존 관례에 맞춰 조정한다. 저장용 source 선택의 유효성은 작업 시작 시 다시 확인하고, 사용자가 보낸 직접 미디어 URL을 신뢰하지 않는다.

### 완료 조건

MP4/HLS 각각 저장→같은 회차 재생→이어보기 유지. 취소·재시작·URL 만료·디스크 부족·잘못된 미디어·중복 요청 처리. 저장본 삭제 후 원격 재생 유지. 프록시/헤더 정책 일치. source 제거 보호. 다운로드 설정 없는 기존 설치의 무변경. 영상이 업데이트 백업에 복제되지 않는지 확인.

## 6. 개발 순서와 제한된 검증

1. **계약 확정:** 최신 main 확인, source/local 재생 분기 및 계정·키즈 경계 검토. 기능별 DTO/완료 조건을 UI 담당과 공유한다.
2. **내장 추천 PR:** 기존 캐시 기반 작은 추천 서비스, 홈 행, 관심 없음·설정. 자료가 없는 경우도 완결된 흐름으로 만든다.
3. **일반 구간 PR:** 공급자 문서 확인 + 소수 표본으로 판본 적합성 결정 → 한 공급자 연결. 부적합하면 다른 공급자를 무제한 시험하지 않고 데이터 제약을 보고한다.
4. **서버 저장 PR:** MP4로 ID·저장소·큐·재생·취소를 먼저 완성 → HLS/자막 → 업데이트·복구 연결. 저장 기능의 완료 조건이 충족되기 전 정식 지원으로 표시하지 않는다.
5. **베타:** 기존 서버 백업 후 개인 환경에서 범용 변경만 검증. 신뢰 가능한 실사이트 자료는 비공개로 유지한다. 정식 발행 전 열려 있는 이슈와 변경분을 다시 확인한다.

테스트는 작업 중 반복적으로 전체 실행하지 않는다. 각 기능의 로직이 모였을 때 핵심 회귀 묶음을 1회 실행하고, 실패/추가 변경이 있는 범위만 재실행한다. UI는 데스크톱·모바일 핵심 경로 한 번씩, 저장은 작은 합성 MP4/HLS와 제한된 실제 소스 표본으로 확인한다. 테스트 위임이 필요하면 사용자 지정 Codex 6.1 sol high 워커를 사용한다. 엔진/사이트 무차별 비교 실험은 하지 않는다.

## 7. 변경과 되돌리기

- 신규 테이블/설정은 가산 방식으로 도입한다. 기존 DB를 열었다는 이유로 기록이나 ID를 재작성하지 않는다.
- 추천/외부 구간은 끌 수 있어야 하고, 새 저장 요청도 차단할 수 있어야 한다.
- 저장 기능을 끄거나 구버전으로 되돌려도 파일을 자동 삭제하지 않는다. 구버전이 저장본을 재생하지 못하는 제한은 명시한다.
- DB rollbackSafe는 가산 테이블이라는 이유만으로 선언하지 않는다. 실제 이전 버전으로 기록·재생·설정 보존을 확인한 뒤 릴리스 정책을 정한다.
- 구현 완료 보고에는 실제 지원 범위와 미지원 포맷/판본을 구분한다. ‘모든 작품 자동 스킵’이나 ‘완전 오프라인’으로 설명하지 않는다.

## 구현 상태 — feat/next-media-features

- 내장 추천과 명시적 `history.read` 플러그인 SDK를 공통 읽기 계층에 연결했다. 기록은 마지막 위치이며 누적 시청시간 수집/통계 화면은 별도 후속 변경으로 남긴다.
- 일반 구간 공급자는 TheIntroDB v3로 선택했다. 실제 길이 ±2초 안에 하나의 알려진 판본만 있을 때 요청하며 미상 판본 병합은 금지한다. 이 길이 조건은 보수적인 필터이지 같은 편집본이라는 증명이 아니다. 구간 위치 실사용 확인은 베타에서 필요하다. 크레딧 끝 null/다중 구간은 적용하지 않는다.
- 일반 구간은 현재 프로필의 실제 재생 세션과 연결하며 로컬/원격/저장본에 조회한다. 기존 파일 마커의 각 구간을 우선하고 다른 구간만 보충한다. 새 공급자의 크레딧 시작으로 자동 다음 회차 시점을 앞당기지 않는다.
- 서버 저장은 전용 볼륨·관리자 용량 설정 후 활성화한다. MP4, 유한 HLS·기본 오디오·AES-128을 지원하고 불명확한 형식은 저장만 미지원 처리한다. 상세 운영/포맷 제한은 [SERVER-SAVES.md](SERVER-SAVES.md).
- 회귀 검사는 프로필/권한/판본/저장 수명에 집중한다. 합성 자료의 실제 FFmpeg 처리와 UI 검증은 운영 검증/전체 확장 호환성 검증과 구분한다. 구현 브랜치 작성만으로 공개/개인 서비스에 배포하지 않는다.

### 구현 검증 기록

- 서버·웹 빌드, 서버·웹 타입 검사 통과. 추천/프로필별 기록 API/플러그인 권한/일반 구간/서버 저장의 집중 회귀 검사와 기존 API·시청기록·소스·플러그인 검사를 통과했다. 호스트에서 `bsdtar`가 없던 플러그인 ZIP 검사는 도구가 포함된 읽기 전용 컨테이너와 임시 출력 폴더로 별도 확인했다.
- 외부 네트워크를 차단한 임시 Docker에서 실제 FFmpeg로 합성 MP4, 일반 HLS, AES-128 HLS, fMP4 HLS, 기본 오디오 분리 master HLS를 저장/검증했다. 저장 완료 후 원본 소스를 실패시켜도 동일 회차 재생·Range 응답·이어볼 위치·기록 보존을 확인했다.
- 저장 중 APK lease 정리/취소/쿼터/경로 검사/원본 소스 삭제 보호는 합성 전송 경계로 검증했다. 실제 APK 제공 사이트의 전체 조합이나 장편 영상의 장기 안정성을 검증했다는 뜻은 아니다.
- 새 저장을 중지해도 기존 저장본을 유지하도록 `MOA_DOWNLOADS_ENABLED=0`을 제공한다. 저장 볼륨은 유지해야 한다.
- 합성 UI의 추천 숨김/복구, 저장 선택/목록/용량/설정, 모바일 회차 아이콘을 확인했다. 실제 플레이어 UI의 부분 구간 응답·실패·재연결 회귀도 루프백 환경에서 통과했다.
- 업데이트/설치 스크립트의 기존 마운트 보존 검사를 통과했다. 실제 릴리스 업그레이드·이전 버전 복구, 공급자 구간의 작품별 정확도와 장편 저장은 베타 단계 검증 범위로 남긴다. 운영 배포와 공개 발행은 수행하지 않았다.
