# 개인 OTT 사용성 후속 후보

2026-11-18 검토. 검색 결과 묶기, 묶인 작품 이어보기, 뒤로 가기 위치 복원에 이어 검토할 작업을 정리했다. 아래 순서는 개발 제안이며 출시 일정은 미정이다.

| 순서 | 사용자에게 필요한 변화 | 구현 시 확인할 점 |
| --- | --- | --- |
| 1 | 내 목록에서 마지막으로 본 회차 이후에 올라온 회차를 확인하고, 최근 업데이트순으로 볼 수 있다. | 실제 소스에서 확인한 회차와 예정 방영일을 구분한다. 기존 회차 관측 기록을 활용하고 저장한 작품 전체를 매 방문마다 조회하지 않는다. 다른 시즌·판본·키즈 프로필을 섞지 않는다. |
| 2 | 시청 기록을 40개 넘게 쌓아도 오래된 기록까지 열 수 있다. | 서버의 다음 페이지를 기존 스크롤 로더로 연결한다. 작품별 보기와 회차별 보기에서 각각 45개 이상으로 확인한다. |
| 3 | 검색창 안내대로 장르를 입력하면 해당 장르의 라이브러리 작품을 찾을 수 있다. | 제목·원제·별칭 검색 순위를 유지한다. 제목에 장르명이 없는 작품도 저장된 장르로 찾는지 확인한다. |
| 4 | 긴 시리즈에서 다른 소스로 바꾸면 해당 소스에 있는 회차 구간이 열린다. | 양쪽 상세가 이미 캐시된 상태에서 150화 작품의 마지막 구간에서 60화 작품으로 전환해 빈 목록이 남는지 재현한다. |
| 5 | 작품 상세에서 전편·후속편·외전을 구분해 찾아간다. | 기존 시즌 선택과 유사작을 재사용한다. 연결이 확인되면 상세를 열고, 불확실하면 제목 검색으로 이어준다. 방영 시각을 표시할 때는 소스 업로드 시각과 구분한다. |
| 6 | TV 리모컨이나 키보드로 긴 줄거리 전체를 읽을 수 있다. | 세 줄 이상인 상세에서 방향키와 Enter로 펼치고 접은 뒤 포커스를 유지하는지 확인한다. |
| 7 | 이어보기 카드에서 어떤 장면까지 봤는지 알아볼 수 있다. | 기존 회차 이미지나 탐색 이미지를 우선 평가한다. 무음 영상 미리보기는 원격 스트림·서버 세션 비용과 터치·리모컨에서의 효용을 측정한 뒤 결정한다. |

### 다시 방문한 화면은 저장본부터 표시

내 목록 최신화와 함께 우선 검토할 항목이다. 관리자 설정의 갱신 빈도는 서버가 원본을 다시 확인하는 주기를 조절한다. 저장된 정보를 화면에 보여줄 수 있는 기간과는 분리한다.

- **작품 정보** — 기존 DB의 제목·포스터·줄거리·회차 목록으로 먼저 그린다. 변경 가능성이 높은 방영작과 기존 연결이 확실한 완결작을 구분해 뒤에서 확인한다. 갱신 실패 시 마지막 성공 데이터를 유지하고, 미검색·실패 응답으로 좋은 데이터를 덮지 않는다.
- **소스 목록** — 검색 결과와 인기·최신 목록은 기존 서버 캐시와 동시 요청 병합을 사용한다. 최근에 방문한 목록이 남아 있으면 먼저 표시하고 실제 변경을 확인한 뒤 교체한다. 재시작 후에도 재사용하되 용량 상한·퇴출은 유지한다. 빈 검색 결과는 짧게 재확인한다.
- **사용자 제어** — 기본은 자동 갱신, 사용자가 새 회차를 기다리는 화면에는 현재 목록만 즉시 확인할 수 있는 동작을 검토한다. 설정을 추가한다면 기존 관리자 화면에 하나의 빈도 선택을 두고 소스마다 TTL 숫자를 설정하도록 요구하지 않는다.
- **정확성** — 소스 삭제·비활성화·권한 변경, 프로필의 키즈 제한, 수동 메타데이터 연결 변경은 바로 반영한다. 개인 시청 위치와 만료 가능한 재생 주소는 공유 작품 정보 캐시에서 제외한다.
- **확인 방법** — 처음 방문, 다음 날 재방문, 원본 오류, 새 회차 도착, 서버 재시작을 재현한다. 첫 카드·재생 버튼이 보이는 시간과 외부 호출 수를 별도로 비교한다.

### 검색·상세의 추가 검토

- 통합 검색은 소스별 첫 페이지를 가져온다. 결과가 더 있거나 일부 소스만 실패한 경우를 빈 검색과 구분하고, 기존 소스별 검색으로 이어갈 수 있는지 확인한다.
- 짧은 간격으로 검색어를 바꿨을 때 이전 검색이 같은 소스의 다음 검색을 얼마나 지연시키는지 측정한다. 같은 요청을 기다리는 다른 사용자가 있으면 해당 작업을 계속한다.
- 작품 수가 많을 때 로컬 제목·원제·별칭 검색과 카드별 회차·진행률 조회 비용을 따로 측정한다. 상세 화면에서도 회차가 준비된 뒤 예고편 등 부가 정보 때문에 재생 버튼이 지연되는지 확인한다.
- 애니 상세의 다음 일본 방영 시각·캐릭터와 성우·주제가 정보는 현재 메타데이터의 누락률과 표시 공간을 보고 판단한다. 기존 인물·일정·유사작 기능과 중복되는 항목은 합친다.

### 자막과 재생 후속 실험

- **판본별 자막 싱크** — 오프닝 이후 한 번만 어긋나는 사례부터 기존 참조 자막 기반 보정을 시험한다. 앞뒤 구간의 일치도가 각각 개선되고 ASS/VTT의 탐색·수동 보정 우선순위가 유지될 때 적용한다.
- **시즌 자막 묶음** — 개별 파일로 판별할 수 없는 경우, 같은 작품·시즌 묶음에서 한 숫자 자리만 달라지고 요청 회차의 후보가 유일한지 확인한다.
- **작품별 번역 용어집** — 회차 사이에서 이름 표기를 일관되게 유지할 수 있도록 출처와 사용자 표기 우선순위, 번역 캐시 버전을 먼저 정한다.
- **기기 업스케일링** — 실제 GPU에서 720p·1080p 재생의 프레임 드롭, 자막과 PiP 동작을 확인한 뒤 기기별 도입 여부를 판단한다.
- **HLS 다운로드 이어받기** — 재시도 전후 영상·음성·구간이 같은 판본인지 검증하는 절차를 먼저 설계한다.
